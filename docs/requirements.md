## 0. 運用の流れ（0.2 で追加）

予測処方量のファイルはエリシアSから月単位でしか出力できないため、次の流れで運用する。

| いつ | 入力 | 処理 | 出力 |
|---|---|---|---|
| 月初 | 前月分の出力ファイル（月単位） | 読み込み → ABC分析（①） → 発注点・在庫上限の算出（②） | (1) 変更すべき発注点のリスト（F-09 の差分版） / (2) C分類の発注品目リスト（F-15） |
| 毎日 | 予測処方量（向こう1週間分） | C品目・フラグ品の必要数の計算（③） | (3) 発注する数量のリスト（F-14） |

- (1) は、エリシアSの発注点を変える必要がある品目だけを載せる。
- (2) は、その月に手入力発注で扱う品目（C区分とフラグ品）の一覧で、毎日の (3) の対象になる。
- (3) の予定使用量の期間は1週間（設定シートで変更できる）とする。

## 1. 対象範囲

| 機能 | 周期 | 目的 |
|---|---|---|
| ① ABC区分の自動判定 | 月次 | 処方回数ランキングから区分を決め、品目マスタに反映する |
| ② 発注点・在庫上限の調整 | 月次（4期の切替時） | A/B品目の発注点と在庫上限を算出し、エリシアSへの設定値を出す |
| ③ 手入力発注リストの作成 | 日次 | 来局予定からC品目・フラグ品の必要数を出し、手打ち発注のリストを出す |

A/B品目を除外するのは③の手入力発注の場面だけです。A/B品目の発注点の調整は②で別に行います。

## 2. 区分の定義

| 区分 | 位置づけ | 発注方法 | 在庫の持ち方 |
|---|---|---|---|
| A | 処方回数の上位。毎日のように出る | 自動発注 | 常備品として相当量を在庫する。在庫上限の配分を優先する |
| B | 中位。定期的に出る | 自動発注（発注点控えめ） | 少なめに在庫する |
| C | 下位。まれに出る | 手入力発注 | 原則持たないか最小限。処方予定が入ったら発注 |
| フラグ | 経過措置品・出荷調整品・保管上限品など | 手入力発注（要判断） | 順位に関係なく自動発注の対象外 |

## 3. 機能要件

### ① ABC区分の自動判定（月次）

| ID | 要件 | 内容 |
|---|---|---|
| F-01 | ランキング取込 | 期間統計表（直近3か月・薬品別）を月次入力シートに読み込み、薬品コード・薬品名・規格・処方回数・使用量を取り出す |
| F-02 | 区分の自動判定 | 処方回数の対数グラフから2つの境界を求め、A/B/Cを自動で判定する（判定方法は4章） |
| F-03 | グラフ表示 | 順位×処方回数（対数目盛り）のグラフに境界線を引いて表示し、薬剤師が目で確認できるようにする |
| F-04 | 品目マスタへの反映 | 判定結果を品目マスタに書き込む。新しい品目は追加し、前回から区分が変わった品目に「変更あり」を表示する |
| F-05 | 区分の手動固定 | 品目マスタの「固定区分」欄に入力された区分を、自動判定より優先する（フラグ品や薬剤師の判断による固定） |

### ② 発注点・在庫上限の調整（月次）

| ID | 要件 | 内容 |
|---|---|---|
| F-06 | 発注点の算出 | A/B品目について、1日あたり平均使用量と、区分ごとの在庫日数から発注点を算出する（Aは多め、Bは少なめ） |
| F-07 | 在庫上限の算出 | 算出した在庫上限と、品目ごとの保管上限（棚・置き場の限界量）の小さい方を採用する |
| F-08 | 在庫限界量の調整 | 薬局全体の在庫の限界を超える場合は、Bの在庫日数から先に減らし、Aの常備量を優先して確保する |
| F-09 | 設定値リストの出力 | エリシアSに設定する発注点・在庫上限の一覧を出力する。前回値との差がある品目だけを抽出した版も出す |

### ③ 手入力発注リストの作成（日次）

| ID | 要件 | 内容 |
|---|---|---|
| F-10 | 予定リスト取込 | 来局予定患者一覧・数量一覧（現在庫）・発注残を日次入力シートに読み込み、薬品ごとに予定使用量を合計する |
| F-11 | A/B品目の除外 | 予定リストの薬品を品目マスタと照合し、A/B区分の品目を計算対象から外す |
| F-12 | 必要数の計算 | C区分とフラグ品について、必要数を計算する（計算式は4章） |
| F-13 | マスタ未登録品 | 品目マスタにない薬品はC区分として扱い、「マスタ未登録」と表示して取りこぼさない |
| F-14 | リストの出力 | 薬品名・規格・必要数・現在庫・予定使用量・理由を出力する。出力は薬品単位の合計のみとし、患者情報は載せない |

## 4. 判定・計算のロジック

### 4-1 対数グラフによるABC判定

処方回数は少数の品目に集中し、下位が長く裾を引く分布になります。順位を横軸、処方回数の対数を縦軸にとると、傾きの異なる3つの区間に分かれます。

- 上位の区間：傾きがゆるやか（毎日のように出る品目）→ A
- 中間の区間：傾きが急（順位とともに回数が落ちる）→ B
- 裾の区間：1回〜数回の品目が平らに並ぶ → C

判定の手順は次のとおりです。

1. 処方回数0の品目を除き、処方回数の多い順に並べる
2. 順位と log(処方回数) の点の並びに、3本の折れ線を当てはめる
3. 折れ点の2か所の組み合わせを総当たりし、折れ線と点のずれ（二乗誤差の合計）が最小になる組み合わせを選ぶ
4. 1つ目の折れ点をA/Bの境界、2つ目をB/Cの境界とする
5. 処方回数0の品目はCとする

裾の1回・2回の品目は段々に並ぶため、境界の候補から外す設定（候補にする最小処方回数）を設けます。参考値として、累積構成比の曲線のひざの位置も併記します。

### 4-2 発注点・在庫上限

```
発注点 ＝ 1日あたり平均使用量 ×（リードタイム ＋ 区分ごとの在庫日数）
在庫上限 ＝ min（1日あたり平均使用量 × 上限日数, 保管上限）
```

### 4-3 手入力発注の必要数

```
必要数 ＝ 予定使用量 ＋ 安全在庫 − 現在庫 − 発注残
→ 包装単位で切り上げ　→ 在庫上限で頭打ち　→ 0以下なら発注なし
```

安全在庫は固定日数とします。新患の導入期と寛解後の漸減期はどちらも低用量で同じ規格帯に集まり、患者数が診察枠でほぼ一定のため、新患による増加と退薬による減少が釣り合うと考えます。この前提は、予定使用量と払出実績の差を月次で確認して監視します。

## 5. 非機能要件

- Excel＋VBAで作成し、店舗PC内で完結する。外部サーバー・外部通信は使わない
- 読み込んだ原本データは書き換えず、取込シートに写してから処理する
- 患者単位のデータは計算の途中でのみ扱い、出力・印刷物には薬品単位の合計だけを載せる
- 区分の判定結果と設定値は、実行日つきで履歴を残す（前回との比較に使う）
- 閾値・在庫日数・リードタイムなどの設定値は、設定シートで変更できるようにする
