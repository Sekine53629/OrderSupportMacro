処方の多い品目はエリシアSの自動発注に任せ、自動発注から漏れる品目だけをマクロで拾って手入力発注リストを出力します。品目の振り分けは月次、必要数の計算は日次で行います。

## 1. 前提

- レセコンはエリシアS。発注は伝票への手打ち発注と、4期ごとに発注点を設定できる自動発注の2通り
- 門前クリニックの処方は30日以内。診察枠（キャパ）で処方枚数の上限がほぼ決まる
- 精神科の処方は「低用量で導入 → 定期で増量 → 寛解後に漸減 → 退薬」の流れをとる
- 院内で使えるのはExcelとVBA。データは店舗外に持ち出さない

## 2. 全体構成

| 処理 | 入力（エリシアSの出力） | マクロの処理 | 出力 |
|---|---|---|---|
| 月次 | 期間統計表（直近3か月・薬品別）、経過措置薬品リスト | A/B/C分類、フラグ付け、安全在庫・監視指標の更新 | 品目マスタ、A/B品目の推奨発注点 |
| 日次 | 来局予定患者一覧、数量一覧（現在庫）、発注残 | C品目・フラグ品の必要数を計算、A/B品目の不足警告 | 手入力発注リスト（薬品単位） |

A/B品目は自動発注に任せ、日次計算の対象から外します。これにより、同じ品目を自動と手打ちの両方で出す二重発注を防ぎます。

## 3. 月次処理：品目の振り分け

### 3-1 A/B/C分類

1. 期間統計表から、直近3か月の薬品別の処方回数・使用量を読み込む
2. 処方回数の多い順に並べ、累積構成比の曲線を作る
3. 曲線の始点と終点を結んだ直線から最も離れた点（ひざ）を、自動発注とする範囲の境界にする
4. 境界より上位をA（自動発注）、境界付近で規則的に処方される品目をB（自動・発注点控えめ）、それ以外をC（手打ち）とする

回数は少なくても、同じ患者に毎月同じ量が出る品目はBに昇格させます。在庫回転率は今の在庫量に左右されるため、補助指標として扱います。

> 注（0.1 時点）: 区分の境界の決め方は、要件定義書 4-1（対数グラフへの3本の折れ線の当てはめ）を正とし、ここに書かれた累積構成比のひざは参考値として併記する。

### 3-2 フラグ品

次の品目は順位に関係なく自動発注の対象外（発注点0）とし、日次で「要判断」として表示します。

- 経過措置品、販売中止予定品（例：リマプロストアルファデクス）
- 出荷調整・限定出荷品
- 高額品、保管場所に上限のある品目（注射・湿布）
- 後発品への切替・採用変更の直後の旧品

## 4. 日次処理：必要数の計算

対象はC品目とフラグ品です。来局予定患者一覧から、次回納品までに来局予定の患者の処方量を薬品ごとに合計し、予定使用量とします。

```
必要数 ＝ 予定使用量 ＋ 安全在庫 − 現在庫 − 発注残
→ 包装単位で切り上げ　→ 在庫上限で頭打ち　→ 0以下なら発注なし
```

- 予定使用量の期間：次回納品までの日数に、予定日のずれを見込んだ前後1〜2日を加える。連休前は設定シートの日数を伸ばす
- 在庫上限で止まった分：理由欄に「分割発注」と表示し、翌日以降の発注につなげる
- A/B品目の不足警告：予定使用量が現在庫＋発注残を上回るA/B品目は、自動発注に任せたまま警告だけ表示する（新規の増量などで発注点が追いついていない場合）

## 5. 安全在庫の考え方

来局予定患者一覧は既存患者の予定なので、新規患者の分は含みません。ただし、新患の導入期と寛解後の漸減期はどちらも低用量で、同じ規格帯に集まります。患者数が診察枠でほぼ一定なら、新患による増加と退薬による減少が釣り合う定常状態になり、予定使用量からのずれは平均するとほぼゼロになります。

このため、新患分を品目ごとに上乗せする計算は行わず、日々のばらつき（新患の集中、予定外の来局）を吸収する固定の安全在庫だけを持ちます。

```
安全在庫 ＝ 1日あたり平均使用量 × 固定日数（初期値は設定シートで指定）
```

## 6. 前提の監視

定常状態の前提は、入力には使わず月次で監視します。

1. 日次で、その日の予定使用量を記録する
2. 後日、払出帳の実績と並べ、差分（実績 − 予定）を品目ごとに蓄積する
3. 月次で、品目ごとの差分の平均がほぼゼロかを確認する
4. プラスに偏り続ける品目だけ、安全在庫の日数を増やす

前提が崩れやすいのは、新しく使われ始めた薬（導入が続き漸減が追いつかない）、増量期だけに使う高い規格、医師の交代や診療枠の増減があったときです。

## 7. シート構成

| シート | 更新 | 内容 |
|---|---|---|
| 設定 | 随時 | 次回納品までの日数、安全在庫の日数、連休カレンダー |
| 品目マスタ | 月次 | 薬品コード、薬品名、分類（A/B/C）、フラグ、包装単位、在庫上限 |
| 月次入力 | 月次 | 期間統計表・経過措置薬品リストの取り込み先 |
| 日次入力 | 日次 | 来局予定患者一覧・数量一覧・発注残の取り込み先 |
| 予実記録 | 日次 | 予定使用量と払出実績、差分の蓄積 |
| 発注リスト | 日次 | 手入力発注リスト（出力） |

手入力発注リストの列：薬品名、規格、必要数（包装単位）、現在庫、予定使用量、理由（C品目／要判断／分割発注／不足警告）

マクロの中では患者単位で計算しても、出力は薬品単位の合計だけとし、患者情報を発注リストに載せません。

## 8. 確認待ちの事項

「エリシアS 発注関連機能 確認作業手順書」（[elixir-check-procedure.md](elixir-check-procedure.md)）での確認結果により、次を確定します。

- 各出力に共通の薬品コード（YJコードなど）が出るか（シート間の結合キー）
- 来局予定患者一覧に薬品名・数量が出るか。出ない場合は患者ごとの前回処方を別に取得する必要がある
- 期間統計表・数量一覧をCSVで出力できるか
- 適正在庫シミュレーションの推奨発注点を、A/B品目の発注点として使えるか
